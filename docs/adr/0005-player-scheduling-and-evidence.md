# ADR 0005 — Pilot scheduling, offline leases, and playback evidence

Status: implementation decision, 2026-09-05. Commercial expansion requires pilot review.

The pilot allocation is a fixed slot in a bounded loop, using the screen's image interval and maximum loop duration captured at operator quote confirmation and shown before client acceptance. This immutable snapshot reserves no capacity until acceptance. One new digital placement reserves one slot; legacy bookings reserve their existing ad-slot count. Reservations use inclusive UTC dates, 24-hour operation, no dayparts. UTC is explicit: local-time/daypart products are rejected until supported, rather than guessing daylight-saving offsets. Inquiry and operator quote confirmation hold no capacity; offline client acceptance and legacy approval acquire the same inventory lock and recheck commitments. Existing commitments without snapshots require operator reconfirmation before campaign-v2 playback. Legacy compatibility placements are never counted twice.

Only one exact approved creative version is scheduled per placement, requiring both client and operator approval for that version and matching campaign/organization. Legacy media uses its existing approval contract. Institutional content fills unused airtime. Emergency overrides interrupt commercial delivery without inventing compensation. Videos must finish inside their reserved interval; interrupted, hidden, failed, or overlong videos never earn completed-play evidence.

The default offline lease is 24 hours as of the 2026-09-27 client request for cached ads to keep playing during a connection loss. `PLAYER_OFFLINE_LEASE_SECONDS` can shorten it but cannot exceed 86400; this is also the maximum disconnected stop/unpublish/revocation delay. Private screens retain a separate 60-second lease. Alerts expire independently and eligible ordinary content resumes. Flag shutdown denies online access and clears local active content; disconnected players stop at lease expiry. No credential is stored in browser storage.

The supported browser stores complete media blobs and an atomic active-manifest pointer in IndexedDB, capped at 256 MiB, with a 50000-event durable outbox. Only one tab may run using a Web Lock. Outbox overflow/storage failure stops evidence-producing playback rather than silently dropping records. A process crash can lose the unfinished play, which is not successful evidence. Completed events are durable before advancing. Rejected records remain in a bounded quarantine for diagnosis, never silently counted or retried forever. Browser eviction/user data deletion cannot guarantee durability; physical kiosk qualification and a real 24-hour soak remain release gates.

Player events extend digital_delivery_events, carry stable UUID, player/session/sequence, immutable manifest and asset references, start/end/duration and receipt time. Ingestion uses the paired cookie, authenticates before deduplication, validates historical authorization and a seven-day receipt window, allows at most two minutes future clock skew, and stores failures and derived issues in one transaction. Late arrival is transport lateness, separate from whether the play completed. These are player reports, not measured audience views or proof that a physical panel was illuminated. Legacy declarations and demo events retain their original provenance.

New server evidence records carry a seven-year retention date under ADR 0003. Existing evidence is not relabeled or deleted. Manifests referenced by that evidence are retained; automated retention cleanup is a separately reviewed operation. Persisted clock observations reject restart clock rollback beyond two minutes; a monotonic in-process deadline bounds a live lease. Browser storage eviction and untrusted device clocks remain hardware qualification concerns.
